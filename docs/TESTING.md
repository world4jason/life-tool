## 測試環境的限制

提供的執行環境禁止 Chromium 透過 HTTP/file URL 導航。沒有更改或規避該政策；測試採用 Playwright `set_content()` 載入本地建置產物，搭配明確的 in-memory Storage shim。匯出測試驗證產生的 Blob bytes 與 SVG XML，不依賴外部下載。

因此「35 組版面檢查」不等於「35 種真實裝置驗證」。也沒有把模擬 Storage 的序列化重載稱為真實 origin 的持久化測試。

## 上線前應完成的人工驗收

1. 在正式 HTTPS 網址分別用桌面 Chrome／Firefox／Safari 與真實 iPhone Safari／Android Chrome 玩一輪。確認鍵盤、觸控、dialog 捲動、日期輸入、橫向時間軸、200% 縮放。
2. 新增卡片後重新整理、關閉再開分頁，確認原生 localStorage 保留。兩個分頁同時修改時，確認衝突提示及匯出／載入最新版本。
3. JSON 匯出後，在另一台裝置匯入；確認事件、主題、路線、計畫、回顧及私密狀態一致。未確認取代前不應變更舊資料。
4. 真實瀏覽器下載 SVG／JSON，確認可開啟、SVG 排除私密事件；不要把私人回顧資料提交到 repo。
5. 確認 GitHub Pages 或其他靜態主機已啟用並可開啟。未完成部署前，不把預期網址當作線上服務。

## 已知範圍與後續

本版是可完整走完的單人遊戲。未提供多人同步、帳號、雲端備份、通知排程、跨年檔案管理、AI 聚類、拖曳卡片、PWA/service worker 或 AntV renderer 整合。

一次只在目前探索桌保留一輪；要開新年先匯出。表單需按儲存，不會逐字保存草稿。方向／路線與卡片有多對多關聯；計畫主幹為一個父節點的樹，不是任意圖。每月最多三張重大事件，另有最多五十張背景卡；主題三十、路線一百二十、計畫二百、回顧五千，匯入檔上限 2 MB。

數量達成不是價值達成，界線在週期尚未結束前只表示目前狀態，不保證期末成功。沒有資料也不表示成功。這些規則需透過使用測試持續確認是否容易理解。
