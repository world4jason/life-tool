# UI / UX 改版走查

本文件是同一位實作者模擬不同角色的檢查，不是獨立設計師、真人受測者或專業教練的評審。畫面、鍵盤與觸控測試由程式執行；沒有將啟發式判斷當成使用者研究。

## 角色與任務

| 角色 | 走查問題 | 對應實作／驗證 |
| --- | --- | --- |
| 新手 | 能否知道選哪些卡、如何成群、何時命名、下一步去哪裡？ | 狀態式提示；示範兩張卡放在第一排；成群後命名欄取得焦點；群組標題旁有「比較做法」。 |
| 教練／引導者 | 系統是否替使用者下結論、把低分當壞事或把分類數量當優先順序？ | 保留有關／無關／未判斷；不按照能量判斷關聯；詞語不自動填成方向或目標。 |
| UI 設計者 | 工具能否被辨識？主要操作會不會藏在長內容後？ | 精簡選取／平移／成群工具；群組主要操作置頂；展開畫布仍保留任務提示與收合按鈕。 |
| 手機使用者 | 必須靠細小拖曳、反覆縮放才能完成嗎？ | 小螢幕預設逐張／清單；可點選卡片並成群、使用移動選單。畫布為可切換視圖。 |
| 鍵盤使用者 | Enter、Space、Escape 的意義是否一致？能否不用拖曳？ | 卡片空白鍵選取；按鈕 Enter 執行本身操作；Escape 取消拖曳或收合畫布；保留移動選單。 |
| 資料／工程 | 移動版面是否誤改分類？進示範、換詞或回顧是否遺失關聯？ | 版面與內容分離；引用卡不複製事件；實際走完群組→方向→兩條路線→行動→回顧；示範與個人紀錄隔離。 |

## 走查中發現並修正

| 嚴重度 | 問題 | 修正 | 驗證方式 |
| --- | --- | --- | --- |
| P1 | 示範要求操作的卡片可能在第一個畫面下方。 | 示範的兩張目標卡放到第一排。 | `canvas.py` 檢查前兩張卡。 |
| P1 | 「比較做法」在群組底部，事件多時難以找到。 | 群組操作移到標題旁，不跟著卡片數量往下沉。 | `canvas-journey.py` 檢查群組 header 的下一步操作。 |
| P1 | 在縮小畫布內命名，文字與輸入區太小。 | 命名使用畫布外、原始尺寸的輸入區；自動取得焦點。 | 成群後檢查可見性與焦點。 |
| P1 | Enter 被父卡片攔截，無法開啟移動選單。 | 僅卡片本身處理 Space／Enter；內部按鈕保留原生行為。 | 鍵盤操作開啟真正的移動對話框。 |
| P1 | 拖曳後的 click 保護曾短暫攔住工具列的復原。 | click 保護僅作用於滑鼠拖曳把手，不攔工具列或鍵盤。 | 拖曳後立即復原、重做。 |
| P1 | 手機切換與提示佔用過多高度，成群按鈕容易離開視窗。 | 方法／視圖合併一排、提示縮短、選卡後成群操作固定在底部。 | 320 / 390 px 清單與選卡畫面檢查。 |
| P1 | 截圖走查發現手機固定操作列繼承 sticky 的 top 值，撐滿整個畫面。 | 明確重設 top:auto 與 margin:0；加入操作列高度、底部位置斷言。 | 320 / 390 / 768 px 選卡後的幾何檢查與實際截圖。 |
| P1 | 鍵盤指令沒有按鈕 dataset，可能在縮放或復原時拋出例外。 | 指令處理容許沒有按鈕來源；補上鍵盤 0 / − 測試。 | 相機更新但內容位元組不變、無 pageerror。 |
| P2 | 平移與選取曾同時呈現選中狀態。 | 以唯一 `aria-pressed` 狀態呈現工具選擇。 | 檢查只有一個啟用工具。 |
| P2 | 已確認方向仍顯示整張可編輯表單。 | 改成方向摘要；按「調整方向」才開啟輸入。 | 從畫布進方向，再選兩條候選路線。 |
| P2 | 畫布佈局亂了，只有拖回原位一種恢復方式。 | 提供「整理」「總覽」「定位」，整理可復原且不修改內容。 | 比對整理前後完整內容位元組。 |
| P2 | 卡片／群組名稱可能包含 HTML 或私密文字。 | 文字轉義；私密遮蔽同步套用到卡片、標籤與內容對話框。 | 私密哨兵與 HTML 字串測試。 |

## 驗證範圍

單元測試涵蓋座標轉換、縮放錨點、佈局清理、參照唯一性、資料不變性、二分類狀態及路線關聯。互動測試操作真正介面，而不是只比較靜態畫面。

- 桌面：框選成群、命名、拖曳換群、拖動群組、版面復原／重做、語意復原／重做、平移、縮放、整理、展開／收合。
- 手機：320 / 390 px 預設清單；切換畫布不改分類；工具列 44 px 觸控區；Chromium CDP 模擬觸控拖曳和雙指縮放。
- 流程：詞／群組→自選方向→兩條候選→選擇理由→行動驗收→回顧；路線圖可編輯實際節點，不是另一份圖面假資料。
- 資料：原 v2 schema 保持；既有 v1 遷移保留；個人與示範位元組隔離；既有保存失敗、跨分頁衝突與匯入確認回歸。

實際數量和個別結果見隨附 `canvas-validation.json`。瀏覽器套件載入精確的單檔 HTML，使用明確的 deterministic Storage shim。

## 尚未證明／仍需人工驗收

本機 HTTP 導航實際回傳 `ERR_BLOCKED_BY_ADMINISTRATOR`，沒有繞過限制。因此本輪沒有驗證原生 HTTP / GitHub Pages localStorage 的持久性，也沒有驗證真實 iPhone Safari、Android、觸控板、螢幕閱讀器或中文輸入法。GitHub Pages 的部署成功不等於以上項目已通過。

縮小畫布時，卡片上的控制項也會縮小；因此手機預設清單，44 px 驗證只涵蓋未縮放的工具列，不宣稱每個縮放狀態下的卡片都達標。JSON 備份不包含版面位置；再次匯入會自動排列，內容與關係仍保留。

沒有真人完成率、完成時間或滿意度數據。下一輪真人驗收應觀察：不用旁人說明能否成群命名、能否指出下一步、誤拖後能否恢復、手機上是否需要頻繁縮放、是否把「有關較多」誤當成「更重要」。

本版不宣稱療效、教練認證或已完成完整無障礙稽核。
